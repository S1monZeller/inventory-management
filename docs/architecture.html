Catalyst Components architecture

An inventory management demo: a Vue 3 single-page app talks to a FastAPI service that filters JSON data held in memory. There is no database, and nothing the server loads is written back to disk.

System overview

Tech stack

Frontend

  • Vue 3 with the Composition API
  • Vue Router 4 in history mode
  • Vite 8 dev server
  • axios for HTTP
  • Hand-written SVG charts

Backend

  • Python 3.11 or newer
  • FastAPI on uvicorn
  • Pydantic response models
  • uv for dependencies

Data

  • JSON files in server/data
  • Loaded once at startup
  • generate_data.py makes sample data

Tests

  • pytest with FastAPI TestClient
  • Backend only, in tests/backend
  • No frontend tests in the repo

Data flow: changing a filter

  1. The user changes a value in FilterBar.vue, for example Time Period or Location.
  2. useFilters updates shared state, and the current view reloads its data.
  3. api.js sends the filters as query parameters, such as /api/orders?warehouse=&month=.
  4. FastAPI filters the in-memory lists and validates the result with Pydantic.
  5. The view stores the raw response in refs, and computed properties derive the KPIs and charts.

Known gaps found while reading the code

GapDetail
Missing endpointsapi.js calls /api/tasks and /api/purchase-orders, but server/main.py defines neither, so those calls return 404.
Missing componentDashboard.vue uses PurchaseOrderModal, which is not in the repo. Vue logs a warning each time the page renders.
Unrouted viewBacklog.vue exists, but client/src/main.js has no route for it, so /backlog does not render a page.
API client bypassReports.vue calls axios directly with a hardcoded URL instead of going through api.js, and it does not use useFilters.
Open network accessuvicorn binds to 0.0.0.0 and CORS allows every origin. This is fine for a local demo with mock data, not for a deployment.
